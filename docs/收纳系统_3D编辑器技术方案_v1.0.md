# 收纳系统 3D 编辑器 — 技术方案 v1.0

## 1. 项目概述

### 1.1 产品定位

面向终端选购用户的在线 3D 收纳配置编辑器。用户选择一个 Block（框体），从目录中拖拽 Item（功能件）和 Riser（增高件）放入 Block 内腔，系统实时校验放置规则并渲染 3D 预览，最终导出 JSON 配置清单和 3MF 打印文件。

### 1.2 核心需求

| 需求 | 说明 |
|---|---|
| Block 选择 | 从 Block 目录中选择一个框体规格 |
| Item/Riser 放置 | 拖拽放入 3D 场景或点击 Cell 选择 |
| Item 拖拽移动 | 已放置的 Item 可在 Block 内拖拽移动到其他位置 |
| 规则校验 | 实时校验 R1-R8 放置规则 |
| 3D 预览 | 实时渲染 Block + 已放置模块的 3D 场景 |
| 材质颜色切换 | 支持切换 3D 打印材料颜色预览效果 |
| Riser 可视化 | Riser 用不同深度颜色渲染，从侧面可见分层 |
| 尺寸标注 | 3D 场景中显示 Block 和选中 Item 的尺寸标注 |
| Riser 配置 | 拖拽或属性面板两种方式给 Item 加 Riser |
| 撤销/重做 | 支持 Ctrl+Z / Ctrl+Shift+Z |
| 导出 JSON | 配置清单，含 Block SKU、Item/Riser 列表及数量 |
| 导出 3MF | 打印用零件文件，所有零件平铺排列 |
| 响应式 | PC 和移动端均可使用 |

### 1.3 技术栈总览

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 框架 | React 18+ | 声明式 UI，R3F 生态成熟 |
| 3D 渲染 | React Three Fiber + @react-three/drei | Three.js 的 React 封装 |
| 状态管理 | Zustand | 轻量、R3F 友好、支持中间件 |
| 样式 | Tailwind CSS | 响应式布局、快速开发 |
| 构建 | Vite | 快速冷启动、Tree-shaking |
| 3MF 导出 | JSZip + 自定义 3MF 序列化 | 纯前端生成 |
| 部署 | 静态托管（Vercel / Netlify / CDN） | 无后端依赖 |

### 2.2 模块职责

**Catalog Panel（目录面板）**

- 展示 Block 列表，用户选择后加载对应 3D 模型
- 展示 Item 和 Riser 目录卡片，含缩略图、名称、尺寸、SKU
- 支持按类型筛选（通用收纳、电池、口红、增高件等）
- 卡片可拖拽（PC: HTML Drag & Drop）或点击（移动端 + PC 备选）

**Viewport（3D 视口）**

- 渲染当前 Block 的 3D 模型
- 渲染所有已放置的 Item 和 Riser（从 Store 读取 placement 列表）
- 渲染网格辅助线（Grid Overlay），标识 Cell 边界
- 处理拖入事件：检测拖拽物进入 Canvas → Raycast 到底板平面 → 吸附到 Cell → 显示合法/非法预览
- OrbitControls：旋转、缩放、平移视角
- 点击已放置 Item 时选中，弹出属性面板（Riser 配置、删除）

**Rule Engine（规则引擎）**

- 纯 TypeScript 模块，零渲染依赖，可独立单元测试
- 核心接口：
  - `validate(state, action) → { valid, reason }` — 校验某个放置/移除操作是否合法
  - `canPlace(state, sku, cell) → boolean` — 某个 Cell 能否放某个 Item
  - `getMaxRiserHeight(state, cell) → number` — 某个位置最大允许 Riser 高度
  - `getAffectedItems(state, removeTarget) → Item[]` — 移除某 Item 后哪些 Item 的 Riser 会失效

**Store（状态中心）**

- 基于 Zustand，含 `immer` 中间件（不可变更新）
- 核心状态：当前 Block、已放置的 Item/Riser 列表、选中 Item、历史栈
- 撤销/重做：自定义 history 中间件，记录每次操作的前后快照

**3MF Exporter（3MF 导出器）**

- 从 Store 读取当前配置
- 从 Three.js 缓存中提取每个 SKU 的 BufferGeometry
- 将每个零件转为打印姿态（底面平放在 Z=0）
- 按行列排列所有零件（含重复件），间隔 10mm
- 组装 3MF XML 结构，用 JSZip 打包，触发下载

## 4. 核心交互流程

### 4.1 选择 Block

```
用户点击 Catalog 中的 Block 卡片
  → Store 更新 block 状态
  → Viewport 加载并渲染 Block GLB 模型
  → Viewport 渲染 Cell 网格辅助线
  → 清空已有 placements
```

### 4.2 放置 Item（拖拽方式）

```
PC 端：
  用户在 Catalog 中拖起 Item 卡片（HTML dragstart）
  → 拖到 Canvas 区域上方（HTML dragover）
  → Canvas 检测到 dragover，取鼠标坐标
  → Raycaster 从鼠标位置投射到 Block 底板平面（Y=0）
  → 计算命中的 Cell 坐标，吸附到网格
  → 调用 RuleEngine.canPlace() 校验
  → 合法：显示绿色半透明预览模型
  → 不合法：显示红色半透明预览模型
  → 用户释放鼠标（HTML drop）
  → 如果合法：Store 添加 placement，记录历史
  → 如果不合法：取消操作

移动端：
  用户点击 Catalog 中的 Item 卡片 → 进入"放置模式"
  → Viewport 中所有可放置的 Cell 高亮为绿色
  → 用户点击某个绿色 Cell
  → Store 添加 placement，记录历史
  → 退出"放置模式"
```

### 4.3 放置 Item（点击方式，PC/移动端通用）

```
用户点击 Viewport 中的一个空 Cell
  → 弹出 Item 选择面板（只显示该位置可放置的 Item）
  → 用户选择一个 Item
  → RuleEngine.canPlace() 校验（应该总是通过，因为已过滤）
  → Store 添加 placement，记录历史
```

### 4.4 配置 Riser

```
用户点击已放置的 Item（选中）
  → 右侧/底部弹出属性面板
  → 显示当前 Riser 配置和最大允许高度（由 RuleEngine.getMaxRiserHeight() 计算）
  → 用户选择 Riser 高度（R5/R10/R20，可叠加）
  → 实时校验，合法则更新 Store，不合法则提示

或拖拽方式：
  用户从 Catalog 拖一个 Riser 到已放置的 Item 上
  → Raycast 命中已有 Item
  → 校验是否可加该 Riser
  → 合法则更新 Store
```

### 4.5 移除 Item

```
用户选中一个 Item → 点击"删除"按钮或按 Delete 键
  → RuleEngine.getAffectedItems() 计算受影响的相邻 Item
  → 如果有受影响的 Item：
    → 高亮显示受影响的 Item（变为黄色/橙色）
    → 弹出确认提示："移除此 Item 将导致 N 个相邻模块的增高件失效，是否继续？"
    → 用户确认 → 移除 Item + 自动移除失效的 Riser → 记录历史
  → 如果无受影响的 Item：
    → 直接移除 → 记录历史
```

### 4.6 导出

```
用户点击"导出 JSON"
  → 从 Store 生成 ExportConfig
  → 序列化为 JSON
  → 触发浏览器下载 .json 文件

用户点击"导出 3MF"
  → 3MF Exporter 读取 Store 中的 placements
  → 汇总所有唯一 SKU 及其数量（Block x1, Item A x3, Riser B x6, ...）
  → 对每个 SKU：
    → 从 Three.js useGLTF 缓存中获取 BufferGeometry
    → 克隆 geometry，变换为打印姿态（底面朝下，Z=0）
    → 按数量在 XY 平面上排列（行列网格，间隔 10mm）
  → 生成 3MF XML（含所有 mesh 对象和 build 指令）
  → JSZip 打包
  → 触发浏览器下载 .3mf 文件
```

### 5.2 坐标系映射

Shapr3D 导出的 GLB 模型使用的坐标系需要和编辑器内的坐标系对齐：

```
编辑器坐标系：
  X → Block 长边方向（左→右）
  Z → Block 短边方向（前→后）（注意：Three.js 中 Y 朝上，Z 朝前）
  Y → 高度方向（底→顶）

Cell (col, row) → 世界坐标：
  x = col * 40 + offsetX    // offsetX = Block 内腔左前角在世界坐标中的 X
  z = row * 40 + offsetZ    // offsetZ = Block 内腔左前角在世界坐标中的 Z
  y = riserTotalHeight       // Item 底面高度 = Riser 总高度

建议将 Block 模型居中于原点，内腔左前角坐标通过 Block 尺寸计算：
  offsetX = -innerWidth / 2    // innerWidth = cols * 40
  offsetZ = -innerDepth / 2    // innerDepth = rows * 40
```

### 5.3 模型加载策略

```
首屏加载：
  - 当前选中 Block 的 GLB（必须）
  - 不预加载所有 Item GLB

懒加载：
  - Item GLB 在用户首次拖拽该 Item 时加载
  - 使用 useGLTF.preload() 在 Catalog 可视区域的 Item 空闲预加载
  - 加载后缓存在 Three.js 内部缓存中，后续复用

加载反馈：
  - 拖拽时如果模型未加载完成，显示占位方块（线框 + 加载指示器）
  - 加载完成后替换为真实模型
```

### 6.3 导出流程

```typescript
async function export3MF(placements: Placement[], block: BlockCatalogItem) {
  // 1. 汇总 BOM
  const bom = buildBOM(placements, block)
  // bom = [{ sku: "41001", quantity: 1 }, { sku: "11002", quantity: 6 }, ...]

  // 2. 收集每个唯一 SKU 的 mesh 数据
  const meshes = new Map<string, BufferGeometry>()
  for (const item of bom) {
    const gltf = useGLTF.getState(item.modelUrl) // 从缓存获取
    const geo = extractGeometry(gltf)             // 提取 BufferGeometry
    const printGeo = toPrintOrientation(geo)      // 旋转到打印姿态
    meshes.set(item.sku, printGeo)
  }

  // 3. 计算每个零件实例的排列位置
  const instances = layoutParts(bom, meshes)
  // instances = [{ sku, transform: Matrix4 }, ...]
  // 行列排列，间隔 10mm

  // 4. 生成 3MF XML
  const modelXml = generate3MFModel(meshes, instances)

  // 5. 打包 ZIP
  const zip = new JSZip()
  zip.file("[Content_Types].xml", contentTypesXml)
  zip.file("_rels/.rels", relsXml)
  zip.file("3D/3dmodel.model", modelXml)

  // 6. 触发下载
  const blob = await zip.generateAsync({ type: "blob" })
  saveAs(blob, "storage-config.3mf")
}
```

### 6.4 Mesh 数据提取

```typescript
function extractGeometry(gltf: GLTF): BufferGeometry {
  // GLB 场景中可能有多个 mesh，需要合并
  const geometries: BufferGeometry[] = []
  gltf.scene.traverse((child) => {
    if (child instanceof Mesh) {
      const geo = child.geometry.clone()
      geo.applyMatrix4(child.matrixWorld) // 应用变换
      geometries.push(geo)
    }
  })
  return mergeBufferGeometries(geometries)
}

function toPrintOrientation(geo: BufferGeometry): BufferGeometry {
  // 确保模型底面在 Z=0 平面上
  geo.computeBoundingBox()
  const minY = geo.boundingBox.min.y
  geo.translate(0, -minY, 0) // 平移到底面贴合 Z=0
  return geo
}
```

### 6.5 零件排列算法

```typescript
function layoutParts(
  bom: BOMItem[],
  meshes: Map<string, BufferGeometry>
): PartInstance[] {
  const GAP = 10 // mm
  const instances: PartInstance[] = []
  let cursorX = 0
  let cursorZ = 0
  let rowMaxDepth = 0

  for (const bomItem of bom) {
    const geo = meshes.get(bomItem.sku)
    geo.computeBoundingBox()
    const width = geo.boundingBox.max.x - geo.boundingBox.min.x
    const depth = geo.boundingBox.max.z - geo.boundingBox.min.z

    for (let i = 0; i < bomItem.quantity; i++) {
      instances.push({
        sku: bomItem.sku,
        position: [cursorX, 0, cursorZ],
      })
      cursorX += width + GAP
      rowMaxDepth = Math.max(rowMaxDepth, depth)

      // 每行放 5 个后换行（可配置）
      if ((i + 1) % 5 === 0) {
        cursorX = 0
        cursorZ += rowMaxDepth + GAP
        rowMaxDepth = 0
      }
    }
    // 每种 SKU 换行
    if (cursorX > 0) {
      cursorX = 0
      cursorZ += rowMaxDepth + GAP
      rowMaxDepth = 0
    }
  }
  return instances
}
```

## 7. 规则引擎技术细节

### 7.1 数据结构

```typescript
// Cell 占用矩阵
type CellGrid = (string | null)[][]
// cellGrid[row][col] = placementId 或 null（空）

// 根据 placements 构建 CellGrid
function buildCellGrid(block: BlockCatalogItem, placements: Placement[]): CellGrid {
  const [cols, rows] = block.cellGrid
  const grid: CellGrid = Array.from({ length: rows }, () => Array(cols).fill(null))
  for (const p of placements) {
    for (let r = 0; r < p.gridSize[1]; r++) {
      for (let c = 0; c < p.gridSize[0]; c++) {
        grid[p.cell[1] + r][p.cell[0] + c] = p.id
      }
    }
  }
  return grid
}
```

### 7.2 R7 校验实现

```typescript
function validateRiserHeight(
  placement: Placement,
  grid: CellGrid,
  placements: Map<string, Placement>,
  block: BlockCatalogItem
): { valid: boolean; reason?: string } {
  const riserTotal = placement.risers.reduce((sum, r) => sum + r.height, 0)
  if (riserTotal === 0) return { valid: true }

  const [cols, rows] = block.cellGrid
  const [pc, pr] = placement.cell
  const [pw, ph] = placement.gridSize

  // 四方向约束值
  const constraints: number[] = []

  // 前方（row 方向 -1）
  constraints.push(getDirectionConstraint("front", pc, pr, pw, ph, grid, placements, block))

  // 后方（row 方向 +1）
  constraints.push(getDirectionConstraint("back", pc, pr, pw, ph, grid, placements, block))

  // 左方（col 方向 -1）
  constraints.push(getDirectionConstraint("left", pc, pr, pw, ph, grid, placements, block))

  // 右方（col 方向 +1）
  constraints.push(getDirectionConstraint("right", pc, pr, pw, ph, grid, placements, block))

  const minConstraint = Math.min(...constraints)

  if (riserTotal >= minConstraint) {
    return {
      valid: false,
      reason: `Riser 高度 ${riserTotal}mm >= 最小约束 ${minConstraint}mm`
    }
  }
  return { valid: true }
}

function getDirectionConstraint(
  direction: "front" | "back" | "left" | "right",
  pc: number, pr: number, pw: number, ph: number,
  grid: CellGrid,
  placements: Map<string, Placement>,
  block: BlockCatalogItem
): number {
  const [cols, rows] = block.cellGrid
  const innerDepth = rows * 40
  let edgeCells: [number, number][] = []

  // 收集该方向外侧的所有 Cell 坐标
  switch (direction) {
    case "front":
      if (pr === 0) return getBorderHeight("front", block)
      for (let c = pc; c < pc + pw; c++) edgeCells.push([c, pr - 1])
      break
    case "back":
      if (pr + ph >= rows) return getBorderHeight("back", block)
      for (let c = pc; c < pc + pw; c++) edgeCells.push([c, pr + ph])
      break
    case "left":
      if (pc === 0) return getSideWallHeight(pr, ph, block)
      for (let r = pr; r < pr + ph; r++) edgeCells.push([pc - 1, r])
      break
    case "right":
      if (pc + pw >= cols) return getSideWallHeight(pr, ph, block)
      for (let r = pr; r < pr + ph; r++) edgeCells.push([pc + pw, r])
      break
  }

  // 检查外侧 Cell 中是否有 Item
  let minHeight = Infinity
  let hasNeighbor = false
  for (const [c, r] of edgeCells) {
    const id = grid[r][c]
    if (id) {
      hasNeighbor = true
      const neighbor = placements.get(id)!
      minHeight = Math.min(minHeight, neighbor.height)
    }
  }

  // 有邻居 → 取最矮邻居高度；无邻居（空位）→ 0
  return hasNeighbor ? minHeight : 0
}

function getBorderHeight(side: "front" | "back", block: BlockCatalogItem): number {
  return side === "front" ? 8 : 68 // 前 Border 净高 8mm，后 Border 净高 68mm
}

function getSideWallHeight(pr: number, ph: number, block: BlockCatalogItem): number {
  // 取 Item 覆盖的最前排行后沿的侧壁净高（最保守值）
  const row = pr // 最前排
  const innerDepth = block.cellGrid[1] * 40
  const externalWidth = innerDepth + 8
  const p = (row + 1) * 40
  const d = p + 4
  const hTotal = 12 + (60 / externalWidth) * d
  return hTotal - 4
}
```

## 11. 3D 预览组件规格

### 11.1 场景环境

**光照方案：简洁平光**

不使用环境贴图和阴影，采用轻量光照方案：

- 1 盏 `ambientLight`（强度 0.6）— 提供基础照明，避免死黑区域
- 1 盏 `directionalLight`（强度 0.8，从斜上方照射）— 给模型一点明暗面层次感
- 不启用 shadowMap — 减少渲染开销，移动端友好
- 不使用 `Environment` HDR 环境贴图

**背景**

纯色浅灰或白色渐变背景（`Canvas` 的 `gl.setClearColor`），不干扰模型观感。

**地面参考**

Block 下方渲染一个淡色圆角矩形平面作为"桌面"参考，让 Block 看起来有"放在某个表面上"的感觉，而不是悬浮在空中。无阴影，仅作视觉锚点。

```tsx
<Canvas>
  <ambientLight intensity={0.6} />
  <directionalLight position={[5, 8, 3]} intensity={0.8} />
  {/* 无 Environment，无 shadow */}
</Canvas>
```

| 参数 | 值 | 说明 |
|---|---|---|

```tsx
function PlacedItem({ placement, color }: Props) {
  const { scene } = useGLTF(placement.modelUrl)
  const clonedScene = useMemo(() => {
    const clone = scene.clone(true)
    clone.traverse((child) => {
      if (child instanceof Mesh) {
        child.material = new MeshStandardMaterial({
          color: color.hex,
          roughness: color.roughness,
          metalness: color.metalness,
        })
      }
    })
    return clone
  }, [scene, color])

  return <primitive object={clonedScene} position={...} />
}
```

## 12. GPU 检测与自适应渲染（高优先级）

流畅度和省电是本项目的高优先级目标。需要在应用启动时检测设备 GPU 能力，自动选择最合适的渲染策略。

### 12.1 GPU 能力检测

使用 `detect-gpu` 库获取设备 GPU 性能等级。该库内置 GPU 基准数据库，可以直接返回 tier 分级。

```typescript
import { getGPUTier } from 'detect-gpu'

interface GPUProfile {
  tier: 0 | 1 | 2 | 3        // 0=不支持 1=低端 2=中端 3=高端
  isMobile: boolean
  gpu: string                  // GPU 名称
  isSoftwareRenderer: boolean  // 是否 CPU 软件渲染（SwiftShader/llvmpipe）
}

async function detectGPU(): Promise<GPUProfile> {
  const result = await getGPUTier()
  return {
    tier: result.tier as 0 | 1 | 2 | 3,
    isMobile: result.isMobile ?? /Mobi|Android/i.test(navigator.userAgent),
    gpu: result.gpu ?? 'unknown',
    isSoftwareRenderer: /swiftshader|llvmpipe|software/i.test(result.gpu ?? ''),
  }
}
```

### 12.2 渲染分级策略

| 参数 | Tier 0 (不支持) | Tier 1 (低端) | Tier 2 (中端) | Tier 3 (高端) |
|---|---|---|---|---|
| **渲染方案** | 降级为 2D 编辑器 | 3D 极简模式 | 3D 标准模式 | 3D 完整模式 |
| **像素比 (dpr)** | — | 1 | [1, 1.5] | [1, 2] |
| **抗锯齿** | — | 关闭 | 开启 | 开启 |
| **网格线** | — | 简化（仅外框） | 完整 Cell 网格 | 完整 Cell 网格 |
| **Ghost 预览** | — | 简单色块 | 半透明模型 | 半透明模型 |
| **选中高亮** | — | 颜色变化 | 颜色变化 | 描边发光 |
| **尺寸标注** | — | 仅 Block | Block + 选中 Item | Block + 选中 Item |
| **浮动标签** | — | 精简 | 完整 | 完整 |
| **地面参考** | — | 关闭 | 简单平面 | 简单平面 |

### 12.3 省电策略

**按需渲染（frameloop: "demand"）**

Three.js 默认每帧都渲染（60fps），但收纳编辑器大部分时间场景是静止的。使用 R3F 的 `frameloop="demand"` 模式，只在场景变化时才触发渲染，空闲时完全不消耗 GPU。

```tsx
<Canvas frameloop="demand">
  {/* 场景内容 */}
</Canvas>
```

需要主动触发重新渲染的时机：
- 用户旋转/缩放/平移视角（OrbitControls 内部会自动 invalidate）
- 放置/移除/移动 Item
- 切换颜色
- 显示/隐藏 Ghost 预览
- 选中状态变化

在 R3F 中通过 `useThree` 的 `invalidate()` 触发：

```typescript
const invalidate = useThree(state => state.invalidate)

function onPlacementChange() {
  updateStore(...)
  invalidate() // 通知渲染器：场景变了，需要重绘一帧
}
```

**拖拽过程中临时切换为连续渲染**

拖拽 Item 过程中需要流畅跟随鼠标，此时临时切换为连续渲染模式：

```typescript
const [dragging, setDragging] = useState(false)

<Canvas frameloop={dragging ? "always" : "demand"}>
```

**视口不可见时暂停渲染**

用户切换到其他 Tab 页或最小化窗口时，完全停止渲染循环：

```typescript
useEffect(() => {
  const handleVisibility = () => {
    if (document.hidden) {
      gl.setAnimationLoop(null)   // 停止渲染循环
    } else {
      invalidate()                 // 恢复后刷新一帧
    }
  }
  document.addEventListener('visibilitychange', handleVisibility)
  return () => document.removeEventListener('visibilitychange', handleVisibility)
}, [])
```

**移动端额外省电措施**

| 措施 | 说明 |
|---|---|
| 强制 dpr=1 | 移动端不使用高像素比，减少一半以上渲染像素量 |
| 关闭抗锯齿 | MSAA 在移动端开销大 |
| OrbitControls 防抖 | 手指离开后立即停止渲染，不做惯性动画 |
| 模型简化 | 如果 GLB 有多级 LOD，移动端使用低精度版本 |

### 12.4 WebGL 不支持时的降级方案

当 `tier === 0`（WebGL 完全不支持或 CPU 软件渲染）时，不应让用户面对空白页面。提供 2D 降级编辑器：

- 使用 2D 俯视网格图代替 3D 视口
- 用色块表示不同 Item 类型
- 保留全部规则校验和放置逻辑
- 保留 JSON 导出（3MF 导出在降级模式下不可用，给出提示）

```tsx
function App() {
  const [gpu, setGPU] = useState<GPUProfile | null>(null)

  useEffect(() => {
    detectGPU().then(setGPU)
  }, [])

  if (!gpu) return <LoadingScreen />

  if (gpu.tier === 0 || gpu.isSoftwareRenderer) {
    return <FallbackEditor2D />   // 2D 降级方案
  }

  return <Editor3D gpuTier={gpu.tier} isMobile={gpu.isMobile} />
}
```

### 12.5 运行时性能监控

在开发阶段和内测阶段，接入简单的性能监控：

```tsx
import { Perf } from 'r3f-perf'

function Viewport({ debug }: { debug: boolean }) {
  return (
    <Canvas>
      {debug && <Perf position="bottom-left" />}
      {/* ... */}
    </Canvas>
  )
}
```

`r3f-perf` 实时显示 FPS、draw calls、三角面数、GPU 内存等指标。正式发布时关闭。

目标性能基线：

| 指标 | 目标值 |
|---|---|
| 空闲帧率 | 0 fps（demand 模式，不渲染） |
| 操作时帧率（PC） | >= 60 fps |
| 操作时帧率（移动端） | >= 30 fps |
| 首次加载到可交互 | < 3 秒（不含模型下载） |
| 单个 GLB 模型大小 | < 200KB（Draco 压缩后） |

## 13. 开发阶段划分

### Phase 1：基础框架 + 3D 渲染

- 项目脚手架（Vite + React + TypeScript + Tailwind）
- GPU 能力检测（detect-gpu）+ Tier 0 降级路由
- 3D 视口：加载并渲染一个 Block GLB 模型
- 自适应渲染参数（dpr、抗锯齿按 GPU tier 分级）
- 按需渲染模式（frameloop: "demand"）
- 光照方案（ambientLight + directionalLight，无阴影）
- OrbitControls（含极角/缩放/平移限制）
- Cell 网格辅助线渲染
- 地面参考平面
- 尺寸标注（Block 长宽）
- 页面不可见时暂停渲染

### Phase 2：目录 + 放置交互

- Catalog 面板 UI（Block 选择 + Item/Riser 列表 + 筛选）
- PC 端拖拽放置（HTML → 3D，Raycaster 网格吸附）
- 移动端点击放置（点击 Item 卡片 → 点击目标 Cell）
- 放置预览 Ghost Item（绿色合法/红色非法）
- HUD 信息覆盖层（Block 名称、Cell 利用率）

### Phase 3：规则引擎 + 视觉反馈

- 实现 R1-R8 全部规则（纯 TypeScript 模块）
- 单元测试覆盖核心规则
- 实时校验 + 合法/非法位置视觉反馈
- 移除联动校验 + 受影响 Item 橙色警告高亮

### Phase 4：3D 内交互增强

- 点击选中 Item（描边高亮 + 浮动信息标签）
- 已放置 Item 的拖拽移动（含实时规则校验）
- 悬停提示（PC 端）
- 右键菜单（PC）/ 长按菜单（移动端）
- 键盘快捷键（Delete、Escape、F 重置视角）

### Phase 5：Riser + 属性面板

- 选中 Item → 属性面板（Riser 配置、删除）
- Riser 配置面板（选择高度、叠加、实时校验最大允许高度）
- Riser 拖拽放置（从目录拖到已有 Item 上）
- Riser 分层渲染（深色区分）
- 选中 Item 时显示 Riser 详情标签

### Phase 6：材质颜色切换

- 预定义色卡（哑光象牙白、浅灰、黑、粉、蓝、绿等）
- 全局颜色切换 + Block/Item 分别颜色
- 运行时材质覆盖（不修改 GLB 原始数据）
- 颜色选择器 UI

### Phase 7：撤销/重做

- Zustand history 中间件（前后快照）
- 快捷键绑定（Ctrl+Z / Ctrl+Shift+Z）
- 所有操作（放置、移动、删除、Riser 配置、颜色切换）均可撤销

### Phase 8：导出

- JSON 配置清单导出（Block + Item 列表 + BOM 数量汇总）
- 3MF 打印文件导出（mesh 提取 → 打印姿态变换 → 行列排列 → ZIP 打包）
- 颜色信息写入导出文件（JSON 中记录颜色选择）

### Phase 9：移动端适配 + 性能优化

- 响应式布局（PC 左右分栏 / 移动端底部抽屉）
- 触摸交互全适配（单指旋转、双指缩放/平移、点击放置、长按菜单）
- 模型懒加载 + Draco 压缩
- 同 SKU 模型实例化（InstancedMesh）
- 移动端可选降低网格线精度
